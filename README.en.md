# MatRAG: search over nonlinear-optics papers and optical constants of crystals

[فارسی](README.md)

MatRAG reads optics papers (PDF), keeps them in a vector database (Qdrant) and, for any question, shows **its
sources with the paper, the page and the place on the page**. The site does not write answers; it finds sources.
Next to the search are refractive-index, phase-matching and SPDC calculators that run entirely in the browser.

It started as an undergraduate physics project at the University of Isfahan ("Design and implementation of an
intelligent information retrieval system for extracting physical properties of materials from scientific papers
with a RAG architecture and vector databases").

## The site

| Tab | What it does |
|---|---|
| Search | Persian or English questions; sources with pages, summary cards of the crystals named, an "AI file" (all sources and the prompt in one file, for any chat assistant) |
| Refractive index | n(λ) from 3,461 refractiveindex.info entries for 2,246 materials plus formulas read from the collection's papers, linked to the source paper |
| Phase matching | angles and QPM periods for SHG, SFG, DFG and OPO, with d_eff, acceptances and walk-off |
| Crystal advisor | every crystal with known nonlinear coefficients tested for a process and wavelengths, ranked, with a suggested cut |
| SPDC | joint spectrum of the photon pair, purity, Schmidt number, pair rate, CAR and fibre coupling |
| Collection | the list of 2,845 papers (2,214 full text, 598 abstract only, 33 metadata only) |

Login is by the login form only (`POST /login`). The owner creates accounts from a Telegram panel; each has an
access level and a daily quota. Paper PDFs are shown only to accounts with PDF access, from a private Worker
(`web-pdfs/`, no public address); no PDF is in this repository.

## Architecture

| Part | Runs on | Does |
|---|---|---|
| `src/matrag/` (Python) | Google Colab or locally | data pipeline: PDF conversion with Docling (and OCR), chunking, bge-base-en-v1.5 vectors, upload to Qdrant, crystal data from `data/rag-optics/*.yml` |
| `web/` (JavaScript) | Cloudflare Workers | the site: hybrid search (dense + BM25 fused with RRF in Qdrant), Persian query translation and a scope check with Workers AI, SubQ reranking, the calculators |
| `notebooks/` | Google Colab | the same pipeline on the Drive collection (generated by `notebooks/build_notebooks.py`) |
| `research_package/` (Python) | locally | reference implementation of the phase-matching and SPDC physics the site's numbers are tested against |
| `scripts/quality/` | GitHub Actions and locally | search-quality evaluation, data map, passage enrichment |

The calculator physics is written twice on purpose: the site computes without a server (JavaScript), and the
Python version with its tests is the reference.

## Search quality

Metric: **paper-level MRR@10** (a paper counts once, at its best passage; 0 past rank 10) on the gold questions in
`data/rag-optics/gold/`, with 95% bootstrap intervals. The questions are split once and for all into dev and test
(`gold/split.csv`): dev is the 200 questions every tuning decision so far was made on; numbers to report should
come from test (`python scripts/quality/search_eval.py --split test`).

| 200 dev questions (2026-10-26) | MRR@10 [95% CI] |
|---|---|
| site order (hybrid) | 0.518 [0.457–0.580] |
| SubQ rerank of the top 30 | 0.590 [0.530–0.650] |
| paired difference SubQ − hybrid | +0.071 [+0.028, +0.116] |

Accepting, for refractive-index questions, the papers with a dispersion formula for the same material
(`paper_formulas.yml`) gives 0.528 [0.468–0.589] for the site order. Differences below about 0.03 between two runs
are noise.

`src/matrag/evaluate.py` reports a different metric ("chunk MRR": chunk level, page-checked, not cut at 10) that
is not comparable with the numbers above.

## Running in Google Colab

1. Open [colab_demo.ipynb](https://colab.research.google.com/github/aminsadidi/RAG/blob/main/notebooks/colab_demo.ipynb),
   choose **Runtime → Change runtime type → T4 GPU** and run the cells in order.
2. Data stays on Google Drive, in `matrag_data`.
3. To upload the collection to the site (no GPU):
   [colab_site.ipynb](https://colab.research.google.com/github/aminsadidi/RAG/blob/main/notebooks/colab_site.ipynb).

A public Gradio link always asks for a user name and password (printed in the notebook).

```
matrag --corpus rag-optics link /content/drive/MyDrive/RAG-Optics
matrag --corpus rag-optics convert --shard 0 --shards 4   # conversion, part 1 of 4
matrag --corpus rag-optics ingest --prune                 # build the database
matrag --corpus rag-optics export-qdrant                  # upload to Qdrant (enrichment fields are kept)
```

## Running locally

```
pip install -r requirements-lock.txt && pip install -e . --no-deps
pytest -q                     # Python tests (no network, no models)
cd web && npm install && npm test
```

## Deploying the site

`cd web && npx wrangler deploy`. Secrets (`npx wrangler secret put NAME`): `QDRANT_URL`, `QDRANT_API_KEY`,
`SITE_PASSWORD` (the owner's password), `SESSION_SECRET` (signs sessions), `CI_USER` and `CI_PASSWORD` (a user
account for the GitHub workflows), and optionally `SUBQ_KEYS`, `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID`,
`TG_WEBHOOK_SECRET`. Counters (quotas, login attempts) live in a Durable Object and the event log in D1 (steps in
`web/wrangler.toml`). The site's address is `SITE_URL` (`wrangler.toml`) and `web/site_url.txt`.

GitHub workflows get their keys from the site with an OIDC token, only on `main`, each only the keys it needs
(`web/src/oidc.js`).
