# MatRAG: جست‌وجو در مقاله‌های اپتیک غیرخطی و ثابت‌های نوری بلورها

[English](README.en.md)

MatRAG مقاله‌های علمی اپتیک (PDF) را می‌خواند، در یک پایگاه داده‌ی برداری (Qdrant) نگه می‌دارد و به هر سؤال
**منبع‌هایش را با نام مقاله، شماره‌ی صفحه و محل روی صفحه** نشان می‌دهد. سایت پاسخ نمی‌سازد؛ منبع پیدا می‌کند.
کنار جست‌وجو، ماشین‌حساب‌های ضریب شکست، تطبیق فاز و SPDC هست که کاملاً در مرورگر اجرا می‌شوند.

این پروژه به‌عنوان پروژه‌ی کارشناسی فیزیک در دانشگاه اصفهان شروع شد (عنوان: «طراحی و پیاده‌سازی سامانه‌ی بازیابی
هوشمند اطلاعات و استخراج خواص فیزیکی مواد از مقالات علمی با معماری RAG و پایگاه داده‌های برداری»).

## سایت

| زبانه | کار |
|---|---|
| جست‌وجو | سؤال فارسی یا انگلیسی؛ منبع‌ها با صفحه، کارت خلاصه‌ی بلورهای نام‌برده، «فایل برای هوش مصنوعی» (همه‌ی منبع‌ها و پرامپت در یک فایل، برای هر چت‌بات) |
| ضریب شکست | n(λ) از ۳٬۴۶۱ داده‌ی refractiveindex.info برای ۲٬۲۴۶ ماده و فرمول‌هایی که از مقاله‌های مجموعه خوانده شده، با پیوند به مقاله‌ی منبع |
| تطبیق فاز | زاویه‌ها و دوره‌ی QPM برای SHG، SFG، DFG و OPO، با d_eff، پذیرش‌ها و walk-off |
| پیشنهاد بلور | همه‌ی بلورهایی که ضرایب غیرخطی‌شان را داریم برای یک فرایند و طول موج آزموده و به ترتیب مرتب می‌شوند، با برش پیشنهادی |
| SPDC | طیف مشترک جفت فوتون، خلوص، عدد اشمیت، آهنگ تولید، CAR و جفت‌شدن به فیبر |
| مجموعه | فهرست ۲٬۸۴۵ مقاله (۲٬۲۱۴ متن کامل، ۵۹۸ فقط چکیده، ۳۳ فقط مشخصات) |

ورود فقط با فرم ورود (`POST /login`) است. حساب‌ها را مالک از پنل تلگرام می‌سازد؛ هر حساب سطح دسترسی و سهمیه‌ی
روزانه‌ی خودش را دارد. فایل PDF مقاله‌ها فقط به حساب‌هایی نشان داده می‌شود که دسترسی PDF دارند و از یک Worker
خصوصی (`web-pdfs/`، بدون آدرس عمومی) خوانده می‌شود؛ هیچ PDFی در این مخزن نیست.

## معماری

| بخش | کجا اجرا می‌شود | چه می‌کند |
|---|---|---|
| `src/matrag/` (Python) | Google Colab یا رایانه‌ی محلی | خط لوله‌ی داده: تبدیل PDF با Docling (و OCR)، قطعه‌بندی، بردار bge-base-en-v1.5، بارگذاری در Qdrant، ساخت داده‌های بلورها از `data/rag-optics/*.yml` |
| `web/` (JavaScript) | Cloudflare Workers | سایت: جست‌وجوی ترکیبی (برداری + BM25 با RRF در Qdrant)، ترجمه‌ی سؤال فارسی و بررسی دامنه با Workers AI، رتبه‌بندی دوباره با SubQ، ماشین‌حساب‌ها |
| `notebooks/` | Google Colab | همان خط لوله روی مجموعه‌ی Drive (از `notebooks/build_notebooks.py` ساخته می‌شوند) |
| `research_package/` (Python) | محلی | نسخه‌ی مرجع محاسبه‌های تطبیق فاز و SPDC که عددهای سایت با آن آزموده می‌شوند |
| `scripts/quality/` | GitHub Actions و محلی | ارزیابی کیفیت جست‌وجو، نقشه‌ی داده‌ها، غنی‌سازی بخش‌ها |

فیزیک ماشین‌حساب‌ها عمداً دو بار نوشته شده: سایت بدون سرور حساب می‌کند (JavaScript) و نسخه‌ی Python با تست‌هایش
مرجع مقایسه است.

## کیفیت جست‌وجو

سنجه: **MRR@10 در سطح مقاله** (هر مقاله یک بار، در بهترین بخشش؛ بعد از رتبه‌ی ۱۰ صفر) روی سؤال‌های مرجع
`data/rag-optics/gold/`، با بازه‌ی اطمینان ۹۵٪ (bootstrap). سؤال‌ها یک بار برای همیشه به dev و test تقسیم شده‌اند
(`gold/split.csv`): dev همان ۲۰۰ سؤالی است که همه‌ی تنظیم‌های تاکنون روی آن انجام شده؛ عددهای قابل گزارش باید از
test بیایند (`python scripts/quality/search_eval.py --split test`).

| روی ۲۰۰ سؤال dev (۲۰۲۶-۱۰-۲۶) | MRR@10 [بازه‌ی ۹۵٪] |
|---|---|
| ترتیب سایت (ترکیبی) | 0.518 [0.457–0.580] |
| رتبه‌بندی دوباره‌ی ۳۰ نتیجه‌ی اول با SubQ | 0.590 [0.530–0.650] |
| تفاوت جفتی SubQ − ترکیبی | +0.071 [+0.028, +0.116] |

با پذیرفتن مقاله‌هایی که فرمول پاشندگی همان ماده را دارند (`paper_formulas.yml`) در سؤال‌های ضریب شکست، ترتیب
سایت 0.528 [0.468–0.589] می‌شود. تفاوت‌های کمتر از حدود ۰٫۰۳ بین دو اجرا در حد نوفه‌اند.

`src/matrag/evaluate.py` سنجه‌ی دیگری می‌دهد («chunk MRR»: در سطح بخش، با بررسی صفحه، بدون برش در ۱۰) که با
عدد بالا قابل مقایسه نیست.

## اجرا در Google Colab

1. [colab_demo.ipynb](https://colab.research.google.com/github/aminsadidi/RAG/blob/main/notebooks/colab_demo.ipynb)
   را باز کنید، **Runtime → Change runtime type → T4 GPU** و سلول‌ها را به ترتیب اجرا کنید.
2. داده‌ها در Google Drive، پوشه‌ی `matrag_data`، می‌مانند.
3. برای بارگذاری مجموعه در سایت (بدون GPU):
   [colab_site.ipynb](https://colab.research.google.com/github/aminsadidi/RAG/blob/main/notebooks/colab_site.ipynb).

لینک عمومی Gradio در کولب همیشه با نام و رمز باز می‌شود (همان‌جا چاپ می‌شود).

```
matrag --corpus rag-optics link /content/drive/MyDrive/RAG-Optics
matrag --corpus rag-optics convert --shard 0 --shards 4   # تبدیل، بخش ۱ از ۴
matrag --corpus rag-optics ingest --prune                 # ساخت پایگاه داده
matrag --corpus rag-optics export-qdrant                  # بارگذاری در Qdrant (فیلدهای غنی‌سازی‌شده حفظ می‌شوند)
```

## استقرار سایت

`cd web && npx wrangler deploy`. رازها (`npx wrangler secret put NAME`): `QDRANT_URL`، `QDRANT_API_KEY`،
`SITE_PASSWORD` (رمز مالک)، `SESSION_SECRET` (کلید امضای نشست‌ها)، `CI_USER` و `CI_PASSWORD` (حساب کاربری
مخصوص گردش‌کارهای GitHub)، و اختیاری: `SUBQ_KEYS`، `TELEGRAM_TOKEN`، `TELEGRAM_CHAT_ID`، `TG_WEBHOOK_SECRET`.
شمارنده‌ها (سهمیه و تلاش‌های ورود) در یک Durable Object و لاگ‌ها در D1 هستند (مراحل در `web/wrangler.toml`).
آدرس سایت در `SITE_URL` (`wrangler.toml`) و `web/site_url.txt` است.

گردش‌کارهای GitHub کلیدهایشان را با توکن OIDC از سایت می‌گیرند، فقط روی شاخه‌ی `main` و هر کدام فقط کلیدهای
لازم خودش را (`web/src/oidc.js`).
